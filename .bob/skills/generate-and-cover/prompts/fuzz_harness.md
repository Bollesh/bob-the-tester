### Harness Template

```python
"""Atheris fuzz harness for {module_name}.

Generated by TestForge Stage 8a.
Target functions: {function_list}
Time budget: {fuzz_seconds}s
"""

import sys
import atheris

# Import the module under test
from {module} import {functions}


def TestOneInput(data: bytes):
    """Fuzz entry point — called by Atheris with random byte sequences."""
    fdp = atheris.FuzzedDataProvider(data)

    # Extract typed inputs from raw bytes
    # Examples:
    #   fdp.ConsumeInt(4)           → 4-byte signed integer
    #   fdp.ConsumeFloat()          → IEEE 754 double
    #   fdp.ConsumeUnicode(100)     → Unicode string up to 100 chars
    #   fdp.ConsumeBool()           → True/False
    #   fdp.ConsumeIntInRange(0, N) → integer in [0, N]
    #   fdp.ConsumeBytes(N)         → N raw bytes

    # Call the target function(s) with fuzzed inputs
    try:
        result = target_function(fuzzed_arg1, fuzzed_arg2)

        # OPTIONAL but recommended: add assertions
        # Assertion-bearing harnesses produce richer crash data
        assert result is not None or expected_none_is_valid
        # Add domain-specific invariants here

    except (ValueError, TypeError, KeyError) as e:
        # Expected exceptions — these are NOT crashes
        # Only list exception types the source explicitly raises
        pass
    # Let all other exceptions propagate — they are genuine crashes


def main():
    atheris.Setup(sys.argv, TestOneInput)
    atheris.Fuzz()


if __name__ == "__main__":
    main()
```

### Rules

1. **The function signature MUST be `def TestOneInput(data: bytes):`** —
   Atheris requires this exact name and signature.

2. **Use `atheris.FuzzedDataProvider`** to convert raw bytes into typed
   values. Never parse `data` directly as a string.

3. **Catch ONLY expected exceptions.** If the source code documents that
   `ValueError` is raised for invalid input, catch it. Let ALL unexpected
   exceptions propagate — they are crashes the fuzzer should find.

4. **Add assertions where possible.** A harness that only catches crashes
   finds fewer bugs than one that also checks invariants (e.g., "result
   must be non-negative", "output length must equal input length").

5. **Target ALL public functions** where feasible. If a function has
   complex object inputs that are hard to fuzz (e.g., database
   connections), skip it and document why.

6. **Do NOT add `time.sleep()` or throttling** — the `run_fuzz` tool
   manages the time budget externally.

7. **Output a single complete Python file** that can be executed directly
   with `python tests/fuzz_{basename}.py`.
