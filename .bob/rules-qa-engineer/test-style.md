# TestForge — House Test Style Rules (QA Engineer Mode)

These rules apply to ALL tests generated by the QA Engineer mode.
They are enforced by Bob during generation and validated mechanically
by the `detect_smells` MCP tool post-generation.

---

## 1. File Organisation

- **One test file per source module.** `src/pricing.py` → `tests/test_pricing.py`.
- **Imports at the top, grouped and separate from test bodies.**
  The `validate_and_keep` tool performs textual insertion — it needs
  imports in a predictable location.

```python
# Good: separable imports
import pytest
from src.pricing import calculate_discount, apply_tax

# Test bodies below...
```

## 2. Naming Conventions

- **Test functions:** `test_{function_under_test}_{scenario}_{expected_outcome}`
- **Examples:**
  - `test_calculate_discount_bulk_order_returns_15_percent`
  - `test_apply_tax_negative_amount_raises_value_error`
  - `test_parse_config_empty_string_returns_defaults`
- **Hypothesis property tests:** `test_prop_{invariant_description}`
  - `test_prop_encode_decode_roundtrip`
  - `test_prop_discount_never_exceeds_price`
- **Regression tests from counterexamples/crashes:**
  `test_regression_{tool}_{short_description}`
  - `test_regression_hypothesis_negative_half_rounding`
  - `test_regression_fuzz_null_byte_in_payload`

## 3. Docstrings

Every test function MUST have a one-line docstring explaining:
1. What scenario it validates (from the edge-case map).
2. Why this scenario matters (boundary, error path, etc.).

```python
def test_calculate_discount_exactly_100_items_boundary():
    """Boundary: 100 items is the threshold for bulk discount — verify it triggers."""
    result = calculate_discount(item_count=100, unit_price=10.00)
    assert result == 8.50  # 15% bulk discount applied
```

## 4. Assertions

### Prefer

- **Exact value assertions:** `assert result == expected_value`
- **Approximate assertions for floats:** `assert result == pytest.approx(expected, rel=1e-6)`
- **Exception assertions:** `with pytest.raises(ValueError, match="negative"):`
- **State-change assertions:** verify that a side effect occurred
  (e.g., database row created, file written, cache invalidated).
- **Behavioural assertions in properties:** assert an invariant holds
  for all generated inputs, not just that the function returns.

### Avoid (smell triggers)

- `assert result is not None` — almost never the right assertion.
- `assert isinstance(result, dict)` — too weak; assert contents.
- `assert True` — vacuous; the `detect_smells` tool flags this.
- `assert len(result) > 0` — assert specific length or contents.
- Bare `try/except` that swallows failures.

## 5. Fixtures and Parametrize

- Use `@pytest.fixture` for shared setup (database connections, temp files,
  mock configurations).
- Use `@pytest.mark.parametrize` when testing the same logic across
  multiple input sets — it keeps the test count honest and the output
  readable.
- Never use `time.sleep()` in tests. If you need to wait for something
  async, use proper async test fixtures or mocking. Sleeps are flagged
  as a smell.

## 6. Test Independence

- Each test must be **independently runnable** — no reliance on execution
  order or shared mutable state.
- Use `tmp_path` (pytest built-in) for file I/O; never write to fixed paths.
- Mock external services; never make real network calls in unit tests.

## 7. Hypothesis Property Tests

- Always constrain strategies to realistic input ranges to avoid
  meaningless edge cases that waste shrinking time.
- Use `@settings(max_examples=200)` unless the skill overrides this.
- Add `@example(...)` decorators for known edge cases from the
  edge-case map to ensure deterministic coverage of critical inputs.
- When Hypothesis finds a counterexample, convert it into a permanent
  named regression test (with the `test_regression_hypothesis_` prefix)
  through the stage-9 regression step.

## 8. Fuzz Harness Style (Atheris)

- The harness function signature must be: `def TestOneInput(data: bytes):`
- Use `atheris.FuzzedDataProvider` to extract typed values from raw bytes.
- Wrap assertions in the harness — a crash without an assertion is still
  valuable (it found an unhandled exception), but an assertion-bearing
  harness produces richer counterexample data.
- Time budget: default 60 seconds. The skill parameter overrides this.

## 9. No Dead Code

- Delete (or never generate) commented-out test code.
- If a test is discarded by `validate_and_keep` or `run_flaky_check`,
  it must not remain in the file. Rollback is the tool's job; Bob must
  not re-insert discarded tests manually.

## 10. Coverage Pragmatism

- Not every line is worth covering. `if __name__ == "__main__":` blocks,
  logging statements, and debug-only code paths are acceptable gaps.
- Document these as intentional gaps in the `explain_gaps` step rather
  than writing contorted tests to reach them.
